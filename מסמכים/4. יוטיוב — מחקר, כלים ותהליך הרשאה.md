לפתוח ערוץ, ולקרוא ולכתוב תגובות.

## 2. פתיחת ערוץ — לא קיים, נקודה

ל-YouTube Data API יש `channels.list` (קריאת פרטי ערוץ) ו-`channels.update`
(עדכון עיצוב של ערוץ קיים), אבל **אין `channels.insert`**. ה-API בנוי לעבוד
מול ערוץ שכבר קיים.

**מה עושים:** פותחים ערוץ ידנית באתר יוטיוב. פעולה חד-פעמית של שתי דקות.
אחריה כל השאר עובד תכנותית.

---

## 3. העלאת סרטון — החסם המרכזי

הפקודה `videos.insert` קיימת, והמכסה דווקא נדיבה: מאז **1.6.2026** יוטיוב
עברה למכסות נפרדות, ולהעלאה יש דלי משלה של **100 העלאות ביום**. המכסה אינה
צוואר הבקבוק. הבעיה אחרת:

> 🔴 **כל סרטון שמועלה דרך ה-API מפרויקט שלא עבר ביקורת תאימות ננעל אוטומטית
> כ"פרטי".** לפי דף העזרה הרשמי של יוטיוב, על נעילה מהסוג הזה **אין אפשרות
> ערעור**, ובעל הערוץ **אינו יכול לשנות את הפרטיות בעצמו**. הסרטון תקוע
> פרטי לתמיד.

זה חל על כל פרויקט API שנוצר אחרי 28.7.2020 — כולל העלאה לערוץ שלכם עצמכם
עם החשבון שלכם. זה לא עניין של הרשאות אלא של סטטוס הפרויקט מול יוטיוב.

### שלוש הדרכים, לפי סדר ההיגיון

1. **להעלות ידנית דרך יוטיוב סטודיו** — הקליפ נבנה אוטומטית עד הסוף, רק
   הלחיצה האחרונה ידנית. אפס סיכון, עובד מיד. **זו ההמלצה כרגע.**
2. **להגיש ביקורת תאימות** — טופס חינמי (`yt_api_form`). דורש תיאור השימוש,
   קישור למדיניות פרטיות ולתנאי שימוש. התשובה לוקחת שבועות ואין התחייבות
   שתאושר. שווה להגיש במקביל אם רוצים אוטומציה מלאה בהמשך.
3. **להעלות דרך ה-API בכל מקרה** — רק אם מקבלים שהסרטון יישאר פרטי לצמיתות
   (למשל לגיבוי או לשיתוף בקישור פנימי). `tools/yt_upload.py` תומך בזה, אבל
   דורש `--i-know-the-risk` מפורש כדי לא לשרוף קליפ מוגמר בטעות.

## 4. תגובות — עובד יפה

| פעולה | עלות מכסה | כמה ביום בפועל |
|---|---|---|
| קריאת עמוד תגובות | 1 יחידה | בלי הגבלה מעשית |
| כתיבת תגובה / תשובה | 50 יחידות | כ-200 |

המכסה המשותפת היא 10,000 יחידות ביום, ומתאפסת בחצות שעון האוקיינוס השקט.

**קריאה** צריכה רק מפתח API — בדיוק כמו Gemini אצלנו.
**כתיבה** צריכה OAuth (ראו סעיף 6).

⚠️ מסנן הספאם של יוטיוב עלול לסמן תגובות אוטומטיות, במיוחד בערוץ חדש. התגובה
תיראה לכם תקינה אבל תוסתר משאר הצופים. לכתוב במידה ובאופן אנושי.

Gemini: שרת MCP מקומי לא עלה בסביבת הענן של Claude Code, וה-MCP-ים כאן מוגדרים
ברמת הסביבה/החשבון ולא דרך קובץ בריפו. אין סיבה להניח שיוטיוב יתנהג אחרת.

**הדפוס שעובד אצלנו הוא קריאת API ישירה עם משתני סביבה** — בדיוק כמו Gemini.
זה מה שנבנה כאן. יתרון נוסף: אין תלות בשרת צד-שלישי שמחזיק את מפתחות הערוץ.

הבדל אחד חשוב מול Gemini: שם מספיק מפתח פשוט. כאן כל כתיבה דורשת OAuth.

## 6. תהליך ההרשאה (OAuth) — מה שפותח העלאה וכתיבה

### למה בכלל
מפתח API מזהה *אפליקציה* ומספיק לקריאת מידע ציבורי. כל פעולה שכותבת בשם
הערוץ דורשת הוכחה שבעל הערוץ אישר אותה — וזה OAuth.

### שלבים (חד-פעמי, כמה דקות)

1. **להפעיל את ה-API** — `console.cloud.google.com` → `APIs & Services` →
   `Library` → לחפש `YouTube Data API v3` → `Enable`.
2. **מפתח לקריאה** — באותו מסך `Credentials` → `Create Credentials` →
   `API key`. לשמור אותו בסביבה כ-`YOUTUBE_API_KEY`.
   בזה לבד כבר עובדת קריאת תגובות.
3. **לקוח OAuth לכתיבה** — `Create Credentials` → `OAuth client ID` →
   סוג האפליקציה `Desktop app`. מקבלים Client ID ו-Client Secret →
   לשמור בסביבה כ-`YT_CLIENT_ID` ו-`YT_CLIENT_SECRET`.
4. **מסך ההסכמה** — `OAuth consent screen`: להוסיף את חשבון הגוגל של הערוץ
   תחת `Test users`, **ולפרסם ל-`In production`**.
   ⚠️ כל עוד הסטטוס `Testing`, טוקן הרענון **פג כל 7 ימים** ותצטרכו להתחבר
   מחדש שוב ושוב. ב-`In production` הוא מחזיק לאורך זמן.
   (יופיע אזהרת "אפליקציה לא מאומתת" — לוחצים `Advanced` → `Go to app`.)
5. **לקבל את הקישור:** `python3 tools/yt_auth.py --auth-url`
   לפתוח בדפדפן, לאשר. הדפדפן ינסה לעבור ל-`localhost` וייכשל — **זה תקין**.
   מעתיקים משורת הכתובת את הערך שאחרי `code=` (עד ה-`&` הראשון אם יש).
6. **להמיר לטוקן קבוע:** `python3 tools/yt_auth.py --exchange "<הקוד>"`
   לשמור את התוצאה בסביבה כ-`YT_REFRESH_TOKEN`. מכאן זה עובד לבד.

### אבטחה
`YT_REFRESH_TOKEN` הוא מפתח לערוץ. **רק במשתני סביבה** (בהגדרות הסביבה
ב-claude.ai/code) — לא בקוד ולא בריפו.

### משתני הסביבה, מרוכז

| משתנה | למה | חובה ל |
|---|---|---|
| `YOUTUBE_API_KEY` | מפתח API | קריאת תגובות |
| `YT_CLIENT_ID` | מזהה לקוח OAuth | כתיבה, העלאה |
| `YT_CLIENT_SECRET` | סוד לקוח OAuth | כתיבה, העלאה |
| `YT_REFRESH_TOKEN` | טוקן רענון קבוע | כתיבה, העלאה |

## 7. הכלים שנבנו

| כלי | תפקיד |
|---|---|
| `tools/yt_auth.py` | הרשאת OAuth — קישור אישור, המרת קוד, הנפקת טוקן שוטף |
| `tools/yt_comments.py` | קריאת תגובות (מפתח API) · כתיבת תגובה ותשובה (OAuth) |
| `tools/yt_upload.py` | העלאת סרטון, עם שערי בטיחות מפני נעילה כפרטי |
| `tests/yt_smoke.sh` | בדיקת קצה-לקצה של שלושתם |
| `tests/yt_mock_api.py` | שרת דמה של YouTube API לבדיקות בלי מפתח ובלי מכסה |

### דוגמאות

```bash
# קריאה
python3 tools/yt_comments.py --video VIDEO_ID
python3 tools/yt_comments.py --video VIDEO_ID --max 200 --order time --json --out c.json

# כתיבה
python3 tools/yt_comments.py --video VIDEO_ID --post "תודה על הצפייה"
python3 tools/yt_comments.py --reply-to COMMENT_ID --post "תשובה"

# העלאה — קודם יבש, תמיד
python3 tools/yt_upload.py --file output/clip.mp4 --title "כותרת" --dry-run
```

## 8. מה נבדק ומה לא

הבדיקה: `bash tests/yt_smoke.sh` — שמונה בדיקות, כולן עברו (13.8.2026).

**הוכח בפועל** מול שרת דמה מקומי:
קריאת תגובות · דפדוף תקין בין עמודים (250 תגובות = 3 עמודים, הסדר נשמר) ·
עצירה נכונה בסוף המאגר בלי לולאה אינסופית · כתיבת תגובה עליונה ותשובה ·
תרגום שגיאות יוטיוב לעברית · בניית קישור ההרשאה על כל רכיביו ·
שערי הבטיחות של ההעלאה (חסימה בלי אישור, קובץ ריק, כותרת ארוכה מדי).

**הוכח מול הרשת האמיתית:** קריאה ל-`googleapis.com` מגיעה ליוטיוב ומקבלת
דחייה מנומקת (`403 — Method doesn't allow unregistered callers`). כלומר
הכתובת, הפרוטוקול והפרמטרים נכונים.

**לא הוכח, ולא ניתן להוכיח בסביבה הזאת:** שגוגל תקבל אישור אמיתי. אין בסביבה
שום אישור גישה ליוטיוב — נבדק ונדחה גם `GEMINI_API_KEY` (השגיאה מלמדת שה-API
לא מופעל באותו פרויקט) וגם `CLOUDSDK_AUTH_ACCESS_TOKEN` (היקף הרשאות לא מתאים).
**האימות הסופי דורש את שלבי סעיף 6 מצד הבעלים.**

## 9. המלצה

1. **ערוץ** — לפתוח ידנית עכשיו, פעם אחת.
2. **קריאת תגובות** — להגדיר `YOUTUBE_API_KEY` (סעיף 6, שלבים 1–2). זה הכי
   קל, והכלי כבר מוכן.
3. **העלאה** — ידנית דרך יוטיוב סטודיו. במקביל אפשר להגיש ביקורת תאימות.
4. **כתיבת תגובות** — לדחות עד שהערוץ פעיל, כדי לא להיתפס כספאם בהתחלה.
